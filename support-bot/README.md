# Support Bot — рефакторинг

Модульная переработка Telegram-бота для регистрации багов/предложений
(консультанты по внедрению + аналитики/разработчики).

## Что изменилось относительно исходного файла

**Исправленные баги:**
1. Кнопка "⏩ Пропустить приоритет" больше не падает с `IndexError`.
2. Ручной ввод `@username` ответственного (`resp_other`) теперь реально
   работает — раньше апдейт "съедался" другим хэндлером на том же фильтре.
3. `add_vote` больше не обращается к закрытому соединению SQLite.
4. Юзернеймы с `_` в имени не обрезаются при выборе ответственного.
5. `/set_auto_close`, `/ban_user`, `/unban_user` — были в `/help`, но не
   были зарегистрированы как команды. Теперь работают.
6. Автозакрытие задач (`auto_close_days`) — настройка существовала в БД,
   но никакая джоба её не использовала. Теперь есть ежедневная джоба.
7. Напоминания переживают рестарт/редеплой бота (раньше терялись).

**Архитектура:**
- SQLite теперь через `aiosqlite` — асинхронно, не блокирует event loop.
- ИИ-клиент через `AsyncOpenAI` — то же самое для запросов к DeepSeek.
- Одно общее соединение с БД вместо `open/close` на каждый запрос.
- Код разбит на модули (`bot/db`, `bot/ai`, `bot/handlers`, `bot/jobs`)
  вместо одного файла на 1000+ строк.
- Есть общий `error_handler` — исключения больше не теряются молча.
- Индексы в БД на часто используемых полях (`status`, `created_at`, ...).
- Защита от CSV/Excel-инъекций в экспортах.
- Все настройки — через переменные окружения (см. `.env.example`),
  ничего не захардкожено (кроме дефолтов).

## База данных

Используется SQLite на **Railway Volume** — переменная
`DATABASE_URL=sqlite:////data/support.db` (Volume должен быть примонтирован
в `/data`). Это дешёвый и простой вариант для текущей нагрузки; если
понадобится масштабирование на несколько инстансов бота — тогда стоит
переезжать на управляемый PostgreSQL (можно сделать отдельным шагом,
слой `bot/db/repository.py` спроектирован так, чтобы SQL-часть было
несложно заменить).

## Установка и запуск локально

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить своими значениями
python -m bot.main
```

## Деплой на Railway

1. Подключить репозиторий к Railway (или залить эту папку как отдельный проект).
2. Создать Volume и примонтировать в `/data`.
3. В Variables задать `BOT_TOKEN`, `DATABASE_URL=sqlite:////data/support.db`,
   `AI_API_KEY` и остальные переменные из `.env.example` по необходимости.
4. Start Command: `python -m bot.main` (уже прописан в `Procfile` / `railway.json`).

## Дальнейшее расширение функционала

Структура рассчитана на добавление новых модулей без переписывания
существующих:
- новая команда/фича → новый файл в `bot/handlers/` + регистрация в `bot/main.py`
- новая таблица → добавить в `SCHEMA_STATEMENTS` в `bot/db/connection.py`
  и CRUD-функции в `bot/db/repository.py`
- новая плановая задача → `bot/jobs/scheduler.py`

Обсудить конкретный список новых фич (SLA-метрики, интеграция с внешней
системой тикетов, роли/права, веб-дашборд вместо HTML-файла и т.д.) —
следующий шаг.
